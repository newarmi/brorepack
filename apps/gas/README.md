# BROREPACK API на Google Apps Script

Бэкенд Mini App на Google Apps Script, база — Google Таблица. Делает то же, что `apps/server`
(Node), но живёт бесплатно в аккаунте Google и не требует своего сервера. Протокол — `docs/gas.md`.

Как устроено:

- Код пишется на TypeScript в `src/`, команда `build` склеивает его (вместе с `zod` и
  `@brorepack/shared`) в один файл `dist/Code.js`, `clasp` заливает его в проект Apps Script.
- Веб-приложение Apps Script (адрес `…/exec`) принимает и запросы Mini App, и апдейты Telegram.
- Заказы лежат в таблице «BROREPACK — заказы», лист «Заказы»: одна строка — один заказ.
- Настройки — «Свойства скрипта» (Script Properties) в настройках проекта.

## Что понадобится

- Google-аккаунт (лучше отдельный для магазина).
- Бот в Telegram (создаётся у [@BotFather](https://t.me/BotFather), он выдаст `BOT_TOKEN`).
- Node 22 и pnpm — как для остального репозитория; зависимости уже стоят после `pnpm install`.
- Ваш Telegram id (узнать: написать [@userinfobot](https://t.me/userinfobot)) — для доступа к админке.

Все команды ниже — из корня репозитория.

## Первый запуск, по шагам

### 1. Разрешите Apps Script API

Откройте <https://script.google.com/home/usersettings> и включите «Google Apps Script API».
Без этого `clasp` не сможет залить код.

### 2. Войдите в Google из терминала

```bash
pnpm --filter @brorepack/gas exec clasp login
```

Откроется браузер — выберите аккаунт магазина и разрешите доступ.

### 3. Создайте проект Apps Script

```bash
pnpm --filter @brorepack/gas run build
pnpm --filter @brorepack/gas exec clasp create --type standalone --title "BROREPACK API" --rootDir dist
```

Появится файл `apps/gas/.clasp.json` с `scriptId` проекта (он в `.gitignore` — у каждого свой).

Если проект уже есть (создали руками на script.google.com): скопируйте `.clasp.json.example`
в `.clasp.json` и вставьте в `scriptId` идентификатор из «Настройки проекта → Идентификаторы →
Идентификатор скрипта».

### 4. Залейте код

```bash
pnpm --filter @brorepack/gas run push
```

Это `build` + `clasp push`. Откройте редактор: `pnpm --filter @brorepack/gas exec clasp open-script`
(или найдите проект «BROREPACK API» на <https://script.google.com>).

### 5. Запустите `setup` и выдайте разрешения

В редакторе вверху выберите функцию **setup** → «Выполнить». Google спросит разрешения:
«Проверить разрешения» → аккаунт → «Дополнительные настройки» → «Перейти на страницу BROREPACK API
(небезопасно)» → «Разрешить». Это ваш собственный скрипт, предупреждение стандартное.

`setup` создаст таблицу «BROREPACK — заказы» у вас на Диске, оформит лист «Заказы», сохранит её id
в свойство `SPREADSHEET_ID` и напишет в журнал ссылку на таблицу. Запускать можно повторно — ничего
не сломает.

### 6. Заполните свойства скрипта

«Настройки проекта» (шестерёнка слева) → «Свойства скрипта» → «Изменить свойства скрипта»:

| Свойство | Что вписать |
|---|---|
| `BOT_TOKEN` | токен бота от @BotFather |
| `WEBAPP_URL` | адрес фронтенда Mini App, обязательно `https://…` |
| `ADMIN_IDS` | Telegram id админов через запятую: `123456789,987654321` |
| `PAYMENTS_MODE` | `telegram` (по умолчанию) — настоящая оплата; `mock` — «оплатить» без денег, только для проверки |
| `PAYMENT_PROVIDER_TOKEN` | токен ЮKassa из @BotFather (нужен при `PAYMENTS_MODE=telegram`) |
| `FACEIT_MODE` | `live` (по умолчанию) — настоящий FACEIT; `mock` — выдуманные профили, только для проверки (в приложении помечаются «Тестовые данные») |
| `FACEIT_API_KEY` | ключ FACEIT Data API: developers.faceit.com → App Studio → своё приложение → API Keys → Server side |
| `DEV_AUTH_BYPASS` | `0`. `1` — только для разработки: пускает кого угодно как `dev:<id>` |
| `WEBHOOK_URL` | адрес `…/exec` из шага 7 |
| `SPREADSHEET_ID` | заполняет `setup` сам |
| `BOT_WEBHOOK_SECRET` | заполняет `setWebhook` сам |
| `LAST_ORDER_ID` | ведётся автоматически (последний выданный номер заказа) — не трогайте |

Свойства читаются на каждый запрос: после правки ничего переразвёртывать не нужно.

### 7. Разверните веб-приложение

В редакторе: «Начать развертывание» → «Новое развертывание» → шестерёнка → «Веб-приложение»:

- «Выполнять как»: **Я** (ваш аккаунт);
- «У кого есть доступ»: **Все** (Anyone) — иначе ни Telegram, ни Mini App не достучатся.

«Развернуть» → скопируйте «URL веб-приложения» (оканчивается на `/exec`). Его нужно вписать:

- в свойство скрипта `WEBHOOK_URL`;
- во фронтенд: `VITE_GAS_URL=<адрес /exec>` и `VITE_API_TRANSPORT=gas` (в `.env` `apps/web`), затем
  пересобрать фронт.

Адрес `/dev` не подходит: он требует входа в Google.

Проверка: откройте адрес `/exec` в браузере — должно показать `{"ok":true,"data":{"ok":true}}`.

### 8. Подключите бота

В редакторе по очереди запустите:

1. **setWebhook** — Telegram начнёт слать сообщения боту на ваш `/exec` (секрет для адреса создастся сам);
2. **setMenuButton** — кнопка «Собрать плашку» в чате с ботом откроет Mini App;
3. **checkConfig** — покажет, какие свойства заданы (значения секретов не печатает), проверит таблицу,
   токен бота и последнюю ошибку доставки вебхука.

Напишите боту `/start` — он должен ответить приветствием с кнопкой.

## Как выкатить новую версию, не меняя адрес

`push` обновляет только черновик проекта, а адрес `/exec` смотрит на зафиксированную версию.
После `pnpm --filter @brorepack/gas run push`:

- в редакторе: «Начать развертывание» → «Управление развертываниями» → карандаш у вашего
  развертывания → «Версия»: **Новая версия** → «Развернуть». Адрес `/exec` остаётся прежним;
- или из терминала: `pnpm --filter @brorepack/gas exec clasp deployments` (узнать id развертывания),
  затем `pnpm --filter @brorepack/gas exec clasp redeploy <id развертывания>`.

Не делайте «Новое развертывание» для обновления — у него будет новый адрес, и придётся заново
менять `WEBHOOK_URL`, `setWebhook` и `VITE_GAS_URL`. (`pnpm --filter @brorepack/gas run deploy` —
это как раз новое развертывание; используйте его только для первого раза.)

Если в `appsscript.json` поменялись разрешения (`oauthScopes`), после `push` запустите любую функцию
в редакторе (например, `checkConfig`) и выдайте разрешения заново.

## Переход с заглушек на боевой режим

**FACEIT.** Зарегистрируйтесь на <https://developers.faceit.com>, создайте приложение и
server-side API key. Впишите его в `FACEIT_API_KEY`, `FACEIT_MODE` → `live`. Профили кэшируются
на 60 секунд.

**Оплата.** В @BotFather: ваш бот → Payments → ЮKassa → сначала тестовый магазин, токен вида
`381764678:TEST:…`. Впишите в `PAYMENT_PROVIDER_TOKEN`, `PAYMENTS_MODE` → `telegram`, проверьте
оплату тестовой картой ЮKassa. Потом подключите боевой магазин и замените токен.

**Перед запуском для клиентов:** `DEV_AUTH_BYPASS` = `0`, `checkConfig` без замечаний.

## Таблица заказов

- Статус хранится кодом: `awaiting_payment` (ждёт оплаты), `paid`, `printing`, `shipped`,
  `delivered`, `cancelled`; на столбце — выпадающий список.
- Меняйте статусы **в админке Mini App**: тогда клиенту придёт сообщение от бота. Правка ячейки
  в таблице сообщений не отправляет.
- Можно сортировать, фильтровать, переставлять столбцы и добавлять свои (заметки и т. п.) — код
  ищет столбцы по заголовку. Не переименовывайте лист «Заказы» и заголовки наших столбцов; если
  столбец пропал, `setup` допишет его справа.
- Удалять строки можно — номера заказов не переиспользуются (счётчик `LAST_ORDER_ID`).
- Даты — в формате ISO по UTC (`2026-10-14T09:30:00.000Z`, это 12:30 по Москве).

## Ограничения Apps Script, о которых стоит знать

Точные цифры — <https://developers.google.com/apps-script/guides/services/quotas>. Для обычного
аккаунта Google примерно так:

- **UrlFetch — 20 000 запросов в сутки** (Workspace — 100 000). Каждый запрос к Telegram и FACEIT —
  один вызов; оплата заказа — сообщение клиенту и по одному каждому админу.
- **30 одновременных выполнений** на пользователя: всплеск из десятков одновременных запросов
  получит ошибку; под нагрузкой магазина плашек хватает с запасом.
- **6 минут на одно выполнение**; наши запросы укладываются в 1–3 секунды.
- **Задержка 1–3 с на запрос**: Apps Script каждый раз «просыпается» и читает таблицу — Mini App
  будет ощутимо медленнее Node-сервера.
- **Свойства скрипта — 50 000 чтений/записей в сутки**: каждый запрос читает их один раз.
- Telegram ждёт ответ на `pre_checkout_query` **10 секунд** — обычно хватает, но в редкие медленные
  минуты Google оплата может сорваться; клиент просто нажмёт «оплатить» ещё раз.
- Таблица рассчитана на сотни и тысячи заказов, не на сотни тысяч: она читается целиком на запрос.

## Логи и диагностика

- Редактор → «Выполнения» (слева): каждый запрос, его журнал и ошибки.
- `checkConfig` в редакторе — что не так с настройками и почему Telegram не доставляет апдейты.
- `pnpm --filter @brorepack/gas run logs` — журнал в терминале; требует привязать проект к Google
  Cloud (`pnpm --filter @brorepack/gas exec clasp setup-logs`), по желанию.
- Бот молчит → `checkConfig` → строка «Последняя ошибка доставки». Частые причины: развёртывание
  с доступом не «Все», в `WEBHOOK_URL` адрес `/dev`, код обновили без новой версии развертывания.
- Отключить бота от Apps Script (например, вернуться на Node-сервер) — функция `deleteWebhook`.

## Разработка

```bash
pnpm --filter @brorepack/gas run build      # dist/Code.js + dist/appsscript.json
pnpm --filter @brorepack/gas run typecheck  # src (типы Apps Script) и тесты
pnpm --filter @brorepack/gas test           # сборка + тесты
```

### Локальный запуск без Google

```bash
pnpm --filter @brorepack/gas run local
```

```bash
VITE_API_TRANSPORT=gas VITE_GAS_URL=http://localhost:8787/exec pnpm --filter @brorepack/web dev
```

Первая команда поднимает эмулятор веб-приложения на `http://localhost:8787/exec`: тот же `dist/Code.js`
в той же песочнице, что и тесты, таблица в памяти, оплата и FACEIT — заглушки, `dev:1` — админ.
Вторая — Mini App, который ходит в эмулятор. Как и настоящий Apps Script, эмулятор не отвечает на
CORS-preflight, так что «непростой» запрос с фронта сразу всплывёт.

Тесты запускают собранный `dist/Code.js` в изолированном `vm`-контексте, где есть только встроенные
объекты JavaScript и эмуляция сервисов Apps Script из `test/gas-env.ts` (таблица, свойства, кэш,
блокировки, UrlFetchApp с фейковыми Telegram и FACEIT). `fetch`, `URL`, `Buffer`, `setTimeout` и
прочего Node там нет — так проверяется, что бандл заработает в Apps Script.

Устройство `src/`:

| Файл | Что внутри |
|---|---|
| `index.ts` | `doGet`, `doPost`: апдейт Telegram или запрос API |
| `handlers.ts` | действия API (`orders.create`, `admin.orders.update`…), права доступа, ошибки |
| `orders.ts` | логика заказов (порт `apps/server/src/orders.ts`) |
| `sheets.ts` | лист «Заказы»: столбцы, маппер строка ↔ `Order`, запись под блокировкой |
| `bot.ts` | вебхук: `/start`, `pre_checkout_query`, `successful_payment`, защита от повторов |
| `telegram.ts` | Bot API через UrlFetchApp, тексты сообщений |
| `faceit.ts` | FACEIT: `mock` и `live` |
| `auth.ts` | проверка `initData` Telegram и `dev:<id>` |
| `config.ts` | свойства скрипта |
| `setup.ts` | `setup`, `setWebhook`, `deleteWebhook`, `setMenuButton`, `checkConfig` |

Точки входа объявляются функциями верхнего уровня в конце `dist/Code.js` (их добавляет `build.mjs`) —
только такие Apps Script видит и показывает в списке функций редактора.
